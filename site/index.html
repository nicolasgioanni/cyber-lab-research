Can a history scan find a deleted secret?

Gitleaks 8.30.1 · Synthetic Git repositories

The working-tree scan found no trace of the synthetic secret after deletion. Scanning the commit history recovered it in each run.

8 of 8 observations matched across 2 independent runs.

Method and results

In each run, one repository received a synthetic secret in its first commit and removed it in the second. A clean control followed the same sequence with ordinary text. Gitleaks scanned both working trees and both commit histories using the same rule.
